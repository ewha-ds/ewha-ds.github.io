## This project

Academic archive site for the EWHA Data Science student council. Content is managed by non-developers through **Pages CMS** (`.pages.yml`).

- Posts live in `src/content/posts/{tech,research,career}/YYYY-MM-DD-<slug>.md` (filename generated by Pages CMS). Schema: `src/content.config.ts`.
- Keep `.pages.yml` fields and `content.config.ts` schema in sync. Never add a required schema field without adding it to `.pages.yml`.
- Goal is continuity of *a* GUI CMS, not Pages CMS specifically. Keep CMS decoupled: no CMS-specific syntax in content, minimal custom features in `.pages.yml`. See README "CMS 교체".
- Never use a frontmatter key named `slug` (Astro glob loader would use it as the entry id and change URLs). The CMS filename key is `urlKey`.
- Publish/visibility logic lives only in `src/lib/posts.ts` (`isPublished`, `isScheduled`). Never filter on `post.data.draft` directly in pages.
- Scheduled publishing depends on the hourly `schedule` cron and `TZ: Asia/Seoul` in `deploy.yml`; keep both.
- `draft` defaults to `true` in the schema; publishing requires explicit `draft: false`.
- Do not reintroduce date subfolders (e.g. `26_09/`) under `src/content/posts/`; Pages CMS cannot create them.
- New Featured Visuals must also be added to the `visual` select options in `.pages.yml`.
- Body is edited with Pages CMS rich-text (markdown output); keep markdown features compatible with it.
- Moving or renaming a published post changes its URL; add the old path to `redirects` in `astro.config.mjs`.
- Article layout lives in `src/components/ArticlePage.astro`, shared by `/posts/[...id]` (published) and `/preview/[...id]` (drafts, noindex).
- Operator docs: `HANDOVER.md` (Korean, non-technical). Developer docs: `README.md`.

## Development

When starting the dev server, use background mode:

```
astro dev --background
```

Manage the background server with `astro dev stop`, `astro dev status`, and `astro dev logs`.
