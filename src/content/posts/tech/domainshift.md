## 들어가며

안녕하세요. 이화여자대학교 데이터사이언스전공 제4대 학생회 피움입니다.

데이터사이언스를 공부하다 보면 모델의 성능을 높이기 위해 다양한 방법을 시도하게 됩니다. 데이터를 정제하고, 모델 구조를 바꾸고, 하이퍼파라미터를 조정하면서 더 높은 정확도를 얻으려 노력합니다.

그런데 테스트 데이터에서 좋은 성능을 보인 모델이 실제 서비스에서는 기대만큼 잘 작동하지 않는다면 어떨까요?

공장 한 곳에서는 불량품을 잘 찾아내던 모델이 다른 공장에서는 정상 제품을 불량으로 판단할 수 있습니다. 인터넷 사진을 잘 이해하던 AI가 의료 영상이나 산업용 검사 이미지에서는 엉뚱한 답을 내놓을 수도 있습니다.

모델이 바뀌지 않았는데 결과가 달라지는 이유 중 하나는 **모델이 마주하는 데이터의 분포가 달라졌기 때문**입니다. [1]

이번 글에서는 이러한 **Domain Shift**가 무엇인지, 어떤 상황에서 발생하는지 살펴보겠습니다. 특히 제조업의 시각적 불량 탐지를 중심으로, 달라진 환경에 대응하는 방법과 관련 연구를 알아보겠습니다.

## 1. 같은 모델인데 왜 성능이 달라질까?

제품 표면의 흠집을 찾아내는 AI를 만든다고 생각해봅시다.

학습 데이터는 다음과 같은 조건에서 수집했습니다.

- 밝은 조명
- 고정된 카메라
- 일정한 촬영 거리
- 동일한 제품 소재

모델은 이 환경에서 정상 제품과 불량 제품을 구분하는 법을 배웠습니다.

그런데 실제로 적용할 공장에서는 조명이 더 어둡고, 카메라의 해상도가 다르며, 제품 표면에 빛이 더 강하게 반사된다면 어떨까요?

사람에게는 여전히 같은 제품이지만, 모델에 입력되는 이미지의 밝기와 질감, 색상은 달라집니다. 모델이 흠집을 구분하는 데 사용하던 단서가 새로운 환경에서는 제대로 작동하지 않을 수 있습니다.

이처럼 **학습 환경과 적용 환경 사이에서 데이터 분포가 달라지는 현상**을 Domain Shift라고 부릅니다.

관련 문헌에서는 **Distribution Shift**라는 표현도 자주 사용합니다. Koh 등의 WILDS 연구는 병원, 촬영 장소, 시간과 지역 등이 달라지는 실제 데이터셋 10개를 구성하고, 학습 환경과 다른 환경에서 모델의 성능이 저하되는 현상을 평가했습니다. 연구에서는 기존의 대응 방법을 적용하더라도 이러한 성능 격차가 남을 수 있음을 보여줍니다.

여기서 두 가지 용어를 알아두면 좋습니다.


| 용어 | 의미 | 제조업 예시 |
| ----------------- | ----------------- | -------------- |
| **Source Domain** | 모델이 학습한 데이터의 환경 | 기존 공장의 검사 이미지 |
| **Target Domain** | 모델을 적용하려는 데이터의 환경 | 새로운 공장의 검사 이미지 |


핵심은 **같은 작업을 수행하더라도, 그 작업에 필요한 데이터가 같은 방식으로 들어오지는 않을 수 있다**는 점입니다.

## 2. Domain Shift는 어디에서 발생할까?

(Domain Shift는 특정 분야에만 존재하는 문제가 아닙니다. 아래는 개념을 이해하기 위한 상황 예시입니다.)


| 분야 | 학습 환경 → 적용 환경 | 달라지는 요소 |
| ---------- | -------------------------- | -------------------- |
| **제조업** | 기존 생산라인 → 새로운 생산라인 | 조명, 카메라, 소재, 촬영 각도 |
| **의료 영상** | 한 병원의 영상 → 다른 병원의 영상 | 장비, 촬영 방식, 환자 구성 |
| **자율주행** | 맑은 날의 도로 → 비나 눈이 오는 도로 | 시야, 반사, 물체의 외형 |
| **자연어 처리** | 상품 리뷰 → 전문적인 금융 문서 | 어휘, 문장 구조, 표현의 의미 |
| **음성 인식** | 조용한 환경 → 소음이 많은 작업장 | 배경 소음, 마이크 특성 |
| **MLLM** | 일반 사진과 질문 → 산업용 이미지와 전문 질문 | 시각적 특징, 전문 용어, 질문 유형 |


- MLLM(Multimodal Large Language Model)은 이미지와 텍스트 등 여러 종류의 정보를 함께 처리하는 대규모 모델입니다.

실제 의료 영상 연구에서도 기관 간 성능 차이가 보고되었습니다. Zech 등은 세 기관의 흉부 X-ray 데이터를 이용해 폐렴 탐지 모델을 평가하고, 내부 평가에서의 성능이 외부 기관에서도 동일하게 유지되는 것은 아님을 보여주었습니다. 또한 영상에는 병원을 식별할 수 있는 단서가 포함되어 있어, 모델이 질병 외의 기관별 특징을 활용할 가능성도 확인했습니다. [7]

다만 전문적인 질문에 틀렸다는 사실만으로 Domain Shift가 원인이라고 단정할 수는 없습니다. 이미지 해상도가 부족하거나, 필요한 지식을 학습하지 못했거나, 애초에 수행하기 어려운 작업일 수도 있습니다.

따라서 먼저 확인해야 할 것은 다음입니다.

> **무엇이 달라졌고, 그 변화가 모델의 판단에 어떤 영향을 주었을까?**

## 3. 새로운 환경에 대응하는 세 가지 접근

Domain Shift에 대응하는 대표적인 접근으로 **Domain Generalization**, **Domain Adaptation**, **Test-Time Adaptation**을 살펴볼 수 있습니다. 이들을 이해하는 중요한 기준은 목표 도메인의 데이터를 언제, 어떤 조건으로 사용할 수 있는가입니다. 다만 세 접근이 완전히 배타적인 것은 아닙니다. 특히 Test-Time Adaptation은 적응이 추론 시점에 이루어진다는 점을 강조하는 설정입니다. [2][3][5]

가장 중요한 구분 기준은 **새로운 환경의 데이터를 언제 사용할 수 있는가**입니다.


| 접근 | 새로운 환경의 데이터 사용 | 핵심 아이디어 |
| ------------------------- | --------------------- | -------------------- |
| **Domain Generalization** | 학습 중 목표 도메인 데이터 없이 진행 | 보지 못한 환경에서도 작동하도록 학습 |
| **Domain Adaptation** | 적응 과정에서 목표 도메인 데이터 사용 | 새로운 환경에 맞게 모델을 조정 |
| **Test-Time Adaptation** | 추론 시 들어오는 데이터 사용 | 적용 중 모델의 일부를 조정 |


### Domain Generalization: 바뀔 환경을 미리 대비하기

새로운 공장의 데이터를 아직 확보하지 못했다면, 기존 데이터만으로 다양한 환경에 대비해야 합니다.

예를 들어 여러 생산라인의 이미지를 함께 학습하거나, 밝기·색상·노이즈·흐림을 변화시키는 데이터 증강을 사용할 수 있습니다.

목표는 특정 카메라의 색감처럼 우연한 단서에만 의존하지 않고, 환경이 바뀌어도 유효한 특징을 배우도록 하는 것입니다. [2]

그러나 데이터를 다양하게 만든다고 항상 성능이 좋아지는 것은 아닙니다. 작은 흠집을 찾는 작업에서 이미지를 지나치게 흐리게 만들면, 정답을 판단하는 데 필요한 정보까지 사라질 수 있습니다.

또한 복잡한 일반화 알고리즘이 단순한 학습 방식보다 항상 우수한 것도 아닙니다. *In Search of Lost Domain Generalization*은 통일된 실험 조건에서 비교했을 때, 잘 구현된 기본 학습 방식인 ERM이 강력한 성능을 보였다고 보고합니다. [2]

따라서 먼저 기본 모델과 적절한 데이터 증강을 기준선으로 삼고, 추가 방법이 실제로 도움이 되는지 비교해야 합니다.

### Domain Adaptation: 새로운 환경의 데이터로 조정하기

새로운 공장의 이미지를 확보했다면, 이를 활용해 모델을 적응시킬 수 있습니다.

정답이 있는 이미지가 있다면 미세조정, 즉 **Fine-tuning**을 고려할 수 있습니다. 정답이 없는 경우에는 **Unsupervised Domain Adaptation**이 대표적인 설정입니다.

이 설정에서는 기존 환경의 정답이 있는 데이터와 새로운 환경의 정답이 없는 데이터를 함께 활용합니다. [3][4]

### Test-Time Adaptation: 적용하면서 조정하기

운영 환경이 계속 변하거나, 적용 전에 충분한 데이터를 모으기 어렵다면 추론 시점에 모델을 조정하는 방법을 고려할 수 있습니다. [5]

다만 모델이 운영 중 바뀐다는 것은 새로운 위험도 생긴다는 뜻입니다. 잘못된 예측을 근거로 업데이트하면 오류가 누적될 수 있기 때문입니다.

이 차이를 이해한 뒤, 대표적인 방법을 살펴보겠습니다.

## 4. 대표 방법론: DANN, Deep CORAL, Tent

### DANN: 어느 환경에서 온 데이터인지 구분하기 어렵게 만들기

- DANN(Domain-Adversarial Neural Network)은 기존 환경과 새로운 환경에서 공통으로 사용할 수 있는 특징을 학습하는 방법입니다. [3]

모델에는 크게 세 가지 구성 요소가 있습니다.

- **Feature Extractor**: 입력에서 특징을 추출
- **Label Predictor**: 특징으로 정답을 예측
- **Domain Classifier**: 특징이 어느 도메인에서 왔는지 구분

학습 목표는 두 가지입니다.

**정답은 잘 예측하고, 도메인은 구분하기 어렵게 만드는 것**입니다.

이를 위해 DANN은 Gradient Reversal Layer를 사용합니다. 도메인 분류기는 도메인을 잘 구분하려고 학습하지만, 특징 추출기는 반대로 도메인 구분을 어렵게 만드는 방향으로 학습합니다. [3]

제조업에 적용한다면, 공장별 색감이나 배경보다 불량 판별에 필요한 특징을 활용하도록 유도하는 접근으로 생각할 수 있습니다.

하지만 도메인 차이를 무조건 없애는 것이 정답은 아닙니다. 실제 결함을 구분하는 중요한 특징까지 제거하면 성능이 나빠질 수 있습니다. [9]

### Deep CORAL: 두 환경의 특징 통계를 맞추기

- Deep CORAL(Correlation Alignment)은 기존 환경과 새로운 환경에서 추출한 특징의 **공분산**을 맞추는 방법입니다. **[4]**

공분산은 여러 특징이 함께 변하는 양상을 나타냅니다. Deep CORAL은 두 도메인의 특징 공분산 차이를 줄이는 손실을 분류 손실과 함께 사용합니다. [4]

DANN이 도메인 분류기와의 경쟁을 활용한다면, Deep CORAL은 특징의 통계적 차이를 직접 줄이는 방식입니다.

다만 통계가 비슷해졌다고 해서 정상과 불량이 올바르게 대응되었다는 뜻은 아닙니다. **도메인을 맞추는 것과 정답을 잘 구분하는 것은 함께 확인해야 하는 별개의 목표**입니다.

### Tent: 예측의 불확실성을 줄이며 적응하기

**Tent**는 대표적인 Test-Time Adaptation 방법입니다.

정답이 없는 테스트 입력에 대해 예측 엔트로피를 줄이고, 정규화 통계와 일부 파라미터를 조정합니다. 전체 모델을 처음부터 다시 학습하는 방식은 아닙니다. [5]

예측 엔트로피가 작다는 것은 모델이 특정 답에 더 높은 확률을 부여한다는 뜻입니다.

그러나 **확신이 커지는 것과 정답에 가까워지는 것은 같지 않습니다.** 이미 틀린 예측을 하고 있다면, 그 예측을 더 확신하게 만들 수도 있습니다.

특히 정상 데이터가 압도적으로 많은 불량 탐지에서는 드문 결함을 놓치지 않는지 점검해야 합니다. 분류 모델을 위한 Tent를 정상 데이터 중심의 이상 탐지 모델에 그대로 적용할 수 있다고 가정해서도 안 됩니다.

## 5. 제조업에서는 왜 더 까다로울까?

제조업에서는 불량 데이터가 충분하지 않은 경우가 많습니다.

정상 제품은 계속 생산되지만, 불량은 드물게 발생하고 형태도 다양합니다. 그래서 정상 이미지를 중심으로 정상의 특징을 학습하고, 여기에서 벗어난 입력을 찾는 **Anomaly Detection**이 활용됩니다. [11]

이때 Domain Shift는 특별히 까다로운 문제를 만듭니다.

새로운 조명 아래에서 촬영한 정상 제품이 기존 정상 이미지와 크게 다르면, 모델은 이를 불량으로 판단할 수 있습니다. 반대로 모든 차이를 새로운 환경의 특성으로 받아들이면 실제 결함까지 정상으로 흡수할 수 있습니다.

즉 모델은 다음을 구분해야 합니다.

> **이 차이는 촬영 환경 때문일까, 실제 제품의 결함 때문일까?**

현장에서는 모델이 환경 변화에 의한 정상품의 차이인지, 실제 불량인지를 구분해 내야 합니다. 이러한 현장의 까다로운 고민을 학술적으로 평가하기 위해 등장한 대표적인 벤치마크가 바로 MVTec AD 2입니다.

산업용 이상 탐지의 대표적인 벤치마크인 **MVTec AD**는 각 범주의 학습 데이터를 결함 없는 이미지로 구성하고, 테스트 데이터에는 정상 이미지와 다양한 결함 이미지를 포함합니다. 이는 정상 데이터에서 학습한 모델이 새로운 입력의 이상을 찾아내는 설정을 제공합니다. [11]

MVTec AD 2는 8개의 산업 검사 시나리오와 8,000장 이상의 고해상도 이미지를 포함합니다. 투명하거나 겹친 물체, 매우 작은 결함 등 어려운 조건을 다루며, 조명 조건이 달라지는 테스트 시나리오를 통해 실제 분포 변화에 대한 강건성을 평가하도록 구성되었습니다. [6]

이 글에서는 이를 중심 사례로 삼을 수 있습니다.

**“조명 변화가 정상 제품의 오탐과 실제 불량의 미탐에 어떤 영향을 주며, 어떤 대응이 이를 줄이는가?”**

여기서 MVTec AD 2는 대응 알고리즘을 제안하는 논문이라기보다, **현실적인 어려움을 평가하기 위한 데이터셋 논문**입니다. DANN, Deep CORAL, Tent와 연결할 때도 각 방법이 요구하는 학습 구조와 데이터 조건을 먼저 확인해야 합니다.

## 6. 실제로 대응한다면 무엇부터 해야 할까?

Domain Shift에 대응하려면 먼저 무엇이 달라졌는지 확인하고, 확보한 데이터에 맞는 방법을 선택해야 합니다. 제조업의 불량 탐지에서는 다음과 같은 순서로 접근할 수 있습니다.

### 먼저 수집 환경과 판정 기준을 확인하기

카메라 노출이나 조명 위치가 바뀌었는지, 이미지 전처리 과정에 문제가 없는지 확인합니다. 품질 기준이 바뀌었다면 정답 데이터도 다시 검토해야 합니다.

촬영 조건을 안정화하거나 전처리를 수정하는 것으로 해결되는 문제라면, 이를 먼저 적용하고 성능을 확인할 수 있습니다. 중요한 것은 **환경의 변화와 실제 결함의 변화를 구분하는 것**입니다.

### 새로운 환경을 별도로 평가하기

전체 이미지를 무작위로 나누는 것만으로는 새로운 공장이나 조명 조건에서의 성능을 충분히 평가하기 어렵습니다.

WILDS 연구는 실제 환경의 분포 변화를 반영한 평가에서, 학습 환경과 다른 환경의 성능이 낮아질 수 있음을 보여주었습니다. [1]

따라서 새로운 공장에 적용할 모델이라면 공장별로, 조명 변화에 대응할 모델이라면 촬영 조건별로 데이터를 분리해 평가해야 합니다. 같은 제품을 연속 촬영한 이미지가 학습과 평가 데이터에 섞이지 않도록 하는 것도 중요합니다.

### 확보한 데이터에 맞는 방법 선택하기

새로운 환경의 데이터를 얼마나 확보했는지, 정답이 있는지에 따라 대응 방법을 선택할 수 있습니다.


| 데이터 확보 상황 | 고려할 수 있는 방법 |
| -------------------------- | ------------------------------------- |
| **새 환경 데이터가 없는 경우** | 여러 환경의 학습 데이터와 데이터 증강을 활용한 일반화 |
| **정답 없는 새 환경 데이터가 있는 경우** | DANN, Deep CORAL 등의 비지도 도메인 적응 |
| **정답 있는 새 환경 데이터가 있는 경우** | 미세조정과 검증 데이터를 이용한 판정 임계값 조정 |
| **추론 시점의 데이터로 적응해야 하는 경우** | 모델 구조와 운영 조건에 맞는 Test-Time Adaptation |


다만 DANN과 Deep CORAL은 소스와 목표 도메인의 데이터를 활용하는 분류 설정에서 제안된 방법입니다. 정상 데이터 중심의 이상 탐지에 적용하려면 학습 구조와 목적에 맞는지 별도로 검토해야 합니다. [3][4]

또한 Test-Time Adaptation의 효과는 초기 모델과 분포 변화의 종류에 따라 달라질 수 있습니다. 운영 중 자동으로 업데이트한다는 이유만으로 성능 향상을 가정해서는 안 됩니다. [10]

정상 데이터의 기준을 갱신할 때도 주의가 필요합니다. 새로운 데이터를 모두 정상으로 간주하면 실제 결함까지 정상의 특징으로 반영될 수 있으므로, 갱신에 사용하는 데이터의 품질을 확인해야 합니다.

### 전체 정확도보다 오류의 종류 살펴보기

불량품이 드문 환경에서는 정확도만으로 모델의 성능을 판단하기 어렵습니다.

예를 들어 불량품이 전체의 1%라면, 모든 제품을 정상으로 판단하는 모델도 정확도는 99%입니다. 하지만 실제 불량은 하나도 찾아내지 못합니다.

따라서 다음 지표를 함께 확인해야 합니다.


| 확인할 항목 | 확인하는 이유 |
| -------------------- | ---------------------------- |
| **불량 재현율** | 실제 불량품 중 얼마나 찾아냈는가 |
| **불량 정밀도** | 불량으로 판단한 제품 중 실제 불량이 얼마나 되는가 |
| **정상 제품 오탐률** | 정상 제품을 얼마나 불량으로 판단하는가 |
| **고정 오탐률에서의 불량 검출률** | 같은 오탐 허용 수준에서 불량을 얼마나 찾아내는가 |
| **조건별 성능** | 특정 조명이나 생산라인에서 성능이 떨어지는가 |


Saito와 Rehmsmeier는 불균형 이진 분류에서 **Precision–Recall 곡선**이 모델 평가에 중요한 정보를 제공한다고 설명했습니다. 불량을 양성 클래스로 두면, 임계값에 따라 불량 정밀도와 재현율이 어떻게 달라지는지 확인할 수 있습니다.

정상 제품이 압도적으로 많은 불균형 데이터에서는 압도적인 True Negative 수치 때문에 ROC 곡선의 성능이 과대평가되기 쉽습니다. 따라서 불량(양성)을 얼마나 정확하게 찾아냈는지에 집중하는 Precision-Recall 곡선을 확인하는 것이 훨씬 실질적입니다. [12]

### 적응 전후를 같은 조건에서 비교하기

대응 방법을 적용한 뒤에는 **적응하지 않은 모델과 적응한 모델을 동일한 평가 데이터에서 비교**해야 합니다.

새로운 환경에서 성능이 높아졌는지뿐 아니라, 기존 환경의 성능이 떨어지지 않았는지도 확인해야 합니다. 모델이나 판정 임계값은 별도의 검증 데이터에서 선택하고, 최종 평가 데이터의 정답을 보고 조정하지 않아야 합니다. 모델 선택과 평가 조건의 중요성은 Domain Generalization과 Test-Time Adaptation 연구에서도 강조됩니다. [2][10]

결국 확인해야 할 것은 단순히 “적응 후 정확도가 높아졌는가?”만이 아닙니다.

**어떤 조건에서 오류가 줄었고, 어떤 오류가 남았으며, 실제 검사 과정에서 허용할 수 있는 수준인지**를 함께 판단해야 합니다.

## 7. 직접 탐구해보기: 조명이 달라지면 모델은 어떻게 반응할까?

작은 실험을 한다면 다음 질문에서 시작할 수 있습니다.

> **밝기와 색감 변화가 불량 탐지에 미치는 영향은 데이터 증강으로 줄일 수 있을까?**

기본 실험은 다음과 같이 구성할 수 있습니다.

1. 원본 이미지로 학습한 기본 모델을 준비합니다.
2. 밝기와 색감 증강을 추가한 모델을 준비합니다.
3. 두 모델을 동일한 원본 평가 데이터에서 비교합니다.
4. 밝기와 색감을 변화시킨 평가 데이터에서도 비교합니다.
5. 정상 오탐과 불량 미탐이 각각 어떻게 달라졌는지 확인합니다.

이때 증강 범위나 판정 임계값을 최종 평가 데이터에 맞춰 고르면 안 됩니다. 별도의 검증 데이터에서 결정한 뒤 평가해야 합니다.

또한 인위적으로 밝기를 조절하는 실험은 통제하기 쉽지만, 실제 조명 변화의 반사와 그림자까지 재현하지는 못합니다. 따라서 가능하다면 MVTec AD 2와 같이 실제 조건 변화가 포함된 데이터로 확장하는 것이 좋습니다. [6]

중요한 것은 단순히 성능 숫자를 비교하는 데서 끝나지 않는 것입니다.

**어떤 변화에서 실패했고, 어떤 방법이 그 실패를 줄였으며, 어떤 실패는 여전히 남았는지**를 설명해야 합니다.

## 마치며

모델의 테스트 성능은 그 모델을 평가한 환경에서의 결과입니다. 새로운 환경에서도 같은 성능이 유지될지는 별도로 확인해야 합니다.

Domain Shift에 대응하려면 먼저 변화의 원인을 구분하고, 새로운 환경의 데이터를 얼마나 사용할 수 있는지 판단해야 합니다. 그 조건에 따라 일반화, 도메인 적응, 테스트 시점 적응을 선택할 수 있습니다.

제조업의 불량 탐지에서는 특히 **환경 때문에 생긴 변화와 실제 결함 때문에 생긴 변화를 구분하는 능력**이 중요합니다.

모델을 평가할 때 다음 질문을 함께 던져보면 어떨까요?

> **“이 모델은 얼마나 정확한가?”**
>
> **“그리고 환경이 바뀌어도 그 정확도를 유지할 수 있는가?”**
