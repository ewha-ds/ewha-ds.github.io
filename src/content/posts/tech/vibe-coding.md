## 1. 바이브 코딩이 정확히 무엇인가

바이브 코딩의 바이브는 vibe, 즉 분위기, 느낌을 의미합니다. 이 용어는 2025년 2월 OpenAI 공동창업자이자 Tesla AI 총괄(Director of AI) 출신의 AI 연구자 안드레아 카파시(Andrej Karpathy)가 제시한 단어로 철저한 사전 설계나 문법 암기 없이, ‘이런 느낌으로 만들어줘’ 같은 직관과 감각에 의존하는 코딩 방식을 말합니다. 구체적으로는 개발자가 일상적인 언어로 아이디어를 설명하면, AI가 이에 대한 코드를 생성하고 수정해주는 소프트웨어 개발 방식입니다.

## 2. 바이브 코딩이 가져온 역할 변화

### 2.1 AI가 코드를 다 짜준다면 코딩을 몰라도 될까?-사람의 역할 변화

바이브 코딩의 개념을 처음 듣는다면 ‘AI가 코드를 작성해 준다면, 우리는 더이상 배울 게 없지 않나?’라는 의문이 들 수 있습니다. 그러나 바이브 코딩은 단순히 AI에게 ‘—해줘’식으로 모든 것을 맡기는 코딩 방법은 아닙니다.

![](</images/vibe coding/mvac2jj5-cft23y21.jpg>)

그림1. 바이브 코딩과 전통적 프로그래밍 과정 비교, 출처:servicenow

위 도식은 바이브 코딩과 전통적인 프로그래밍의 개발 과정을 비교한 것으로, 두 방식의 차이가 '코드를 누가 쓰는가'에 그치지 않고 '사람이 어떤 일에 시간을 쓰는가'에 있음을 보여줍니다.

전통적인 방식은 문제와 요구사항을 정의하고, 기술 스택을 고르고, 코드를 직접 작성하고, 개발 환경을 관리하고, 디버깅과 테스트를 거쳐, 통합과 배포에 이르는 여섯 단계를 사람이 모두 직접 수행합니다.

반면 바이브 코딩은 해결하려는 문제를 자연어로 설명하면 AI가 이를 해석해 코드를 생성하고, 사용자가 결과를 검토·테스트한 뒤, 후속 프롬프트로 다듬어 배포하는 단계로 이루어집니다. 기술 스택 선택, 수작업 코딩, 환경 관리 같은 부담스러운 과정은 AI가 맡아 단계가 줄어들었지만, 도식을 자세히 보면 '결과를 검토하고 테스트하는' 단계와 '후속 프롬프트로 개선하는' 단계는 여전히 사람의 몫으로 남아 있습니다.

> *즉 바이브 코딩에서 사람은 코드를 쓰는 작성자에서 문제를 정의하고 결과를 판단하는 지시자이자 검토자로 역할이 바뀐 것입니다.*

그러나 더이상 코드를 짜지 않아도 된다는 사실이 과정에 대한 이해 없이 누구나 개발을 할 수 있다는 사실을 의미하는 것은 아닙니다.

- **요구사항 정의**: 어떤 기능이 필요한지 구체적으로 설명하기
- **코드 이해**: AI가 만든 코드가 어떤 일을 하는지 파악하기
- **디버깅**: 결과가 이상할 때 원인을 추적하기
- **검증과 보안**: 계산 결과가 맞는지, 개인정보나 비밀 키가 노출되지 않는지 확인하기

사람의 역할이 지시자로 바뀐만큼, 프로젝트에 필요한 기능과 이에 쓰인 코드에 대한 전반적인 이해가 중요해집니다.

### 2.2 그렇다면 AI의 역할은 어떻게 변화했나

*"코드를 짜는 도구"에서 "개발을 대신 수행하는 파트너"로*

![](</images/vibe coding/mvac2qak-qnbt40gq.jpg>)

2021년경 AI는 개발자가 코드를 입력하는 도중 다음에 올 코드 일부를 제안해 주는 자동완성 수준이었습니다. 

2022년 ChatGPT가 등장하면서 자연어로 질문하고 코드를 받아 볼 수 있게 되었지만, 이 역시 사람이 답변을 복사해 직접 프로젝트에 옮기고 실행하며 오류를 잡아야 하는 대화형 보조에 머물렀습니다. 

그러나 Cursor, Claude Code와 같은 에이전트형 코딩 도구가 나오면서 상황이 달라졌습니다. 이제 AI는 여러 파일을 직접 만들고 코드를 실행하며, 오류가 나면 스스로 원인을 찾아 고치는 단계까지 나아갔습니다.

바이브 코딩은 바로 이런 변화 위에서 가능해진 방식으로, AI가 '코드를 짜는 도구'에서 '개발을 대신 수행하는 파트너'로 역할이 바뀌면서 사람은 구현의 세부 과정보다 무엇을 만들지 정하고 결과를 검토하는 일에 집중하게 되었습니다.

## 3. 성공적인 바이브 코딩하기

### 3.1 프롬프트 엔지니어링과 CoT

그렇다면 AI를 유능한 파트너로 사용하기 위해서 우리는 어떤 능력을 갖춰야할까요?

대표적으로 **적절한 프롬프트를 작성하는 능력**이 있습니다. 이를 프롬프트 엔지니어링(Prompt Engineering)이라고 하는데요. 프롬프트 엔지니어링은 AI 모델로부터 원하는 결과를 얻기 위해 입력하는 지시문을 설계하고 최적화하는 과정입니다.

바이브 코딩에서는 이러한 역량이 특히 중요합니다. 개발하고자 하는 프로그램의 기능과 요구사항을 구체적으로 전달할수록 AI가 의도에 맞는 코드를 생성할 가능성이 높아지기 때문입니다.

***적절한 프롬프트?***

- ***설계 먼저, 구현은 나중에:** "코드를 작성하기 전에 어떤 방식으로 만들지 먼저 설명해 줘"라고 요청하면, 잘못된 방향을 코드가 쌓이기 전에 바로잡을 수 있습니다.*
- ***이유를 함께 물어보기:** "왜 이렇게 작성했는지 설명해 줘"를 덧붙이면 AI의 판단 근거를 확인할 수 있고, 이 과정에서 독자 스스로 코드를 이해하는 힘도 길러집니다.*

프롬프트 기법에는 예시 없이 바로 요청하는 제로샷, 예시를 함께 주는 퓨샷 등 여러 가지가 있습니다. 이 글에서는 바이브 코딩에서 특히 효과가 큰 CoT(Chain of Thought, 사고의 연쇄) 프롬프팅만 소개하고, 나머지는 다음 글에서 다루겠습니다.

### 3.2 Chain of Thought(CoT) 프롬프팅

CoT 프롬프팅은 AI에게 답이나 결과물만 요구하지 않고, 중간 사고 과정을 단계별로 거치도록 유도하는 기법입니다. 사람도 복잡한 문제를 풀 때 바로 답을 쓰기보다 풀이 과정을 적어 가며 푸는 것이 정확한 것처럼, AI도 단계를 나누어 생각하게 하면 오류가 줄어듭니다.

### 3.3 CoT 실제로 해보기

투표 웹사이트 제작을 CoT 프롬프팅을 이용한 방법과 이를 이용하지 않고 만든 방법을 비교해보았습니다. 이용한 AI모델은 **GPT-6 Luna**와 **Claude** 입니다.

![](</images/vibe coding/mvad6j7q-fl9vlcoi.png>)

![](</images/vibe coding/mvad6ao5-fd3kwclp.png>)

- **GPT 사례**

두 경우 모두 GPT는 "투표 웹사이트 '모아'를 만들었다"며 투표하기, 결과 확인, 투표 만들기, 반응형 디자인 기능을 갖춘 완성품인 것처럼 안내했고, 텍스트 응답만 보면 두 결과는 사실상 같았습니다. 그러나 직접 눌러 보니 일반 프롬프트로 만든 사이트는 기존 투표 참여는 가능했지만 새 투표 만들기 버튼이 작동하지 않았고, CoT 프롬프트로 만든 사이트는 투표 참여 버튼까지 작동하지 않았습니다.

이 사례는 CoT 프롬프팅이 항상 더 나은 결과를 보장하는 것은 아니며, 한 번의 실행만으로 어느 쪽이 더 낫다고 단정하기도 어렵다는 점을 보여줍니다.

그러나 더 중요한 점은 AI가 두 경우 모두 자신 있게 "완성했다"고 말했지만 실제로는 핵심 기능이 동작하지 않았다는 것입니다. AI의 설명이 아무리 그럴듯해도 결과물을 직접 실행해 확인하는 사람의 검토가 반드시 필요하며, 이는 바이브 코딩에서 사람이 '지시자이자 검토자'로 남아야 하는 이유이기도 합니다. *(1회 실행 결과이며, 같은 프롬프트라도 실행할 때마다 결과는 달라질 수 있습니다.)*

- **Claude 사례**

같은 방식으로 Claude에도 일반 프롬프트와 CoT 프롬프트를 각각 입력해 보았습니다. 

일반 프롬프트의 결과물은 바로 실행할 수 있는 형태로 나왔고, 한 사람이 같은 투표에 중복으로 참여할 수 없었으며, 선택지가 0개 또는 1개인 투표는 만들어지지 않았습니다. 반면 CoT 프롬프트에서는 Claude가 요구사항 정리, 구조 설계, 악용 가능성 검토까지 단계별로 상세히 설명했고, 코드 투표와 쿠키·IP 기반 중복 방지, 입력값 검증 같은 보안 장치도 갖춘 설계를 내놓았습니다. 그러나 결과물이 서버와 데이터베이스를 포함한 여러 개의 파일로 구성되어 있어 설치와 서버 실행 과정이 필요했고, 실제로는 실행해 볼 수 없었습니다. 또한 Claude는 공개 투표의 중복 방지가 완벽하지 않다는 등 남아 있는 한계를 스스로 밝혔습니다.

이 사례는 CoT 프롬프팅이 AI의 설계를 더 깊고 꼼꼼하게 만들어 주지만, 그만큼 결과물이 복잡해져 초보자가 바로 쓰기 어려워질 수 있음을 보여줍니다. (각 프롬프트를 1회 실행한 결과이며, 실행할 때마다 결과는 달라질 수 있습니다.)

> *결국 GPT와 Claude 두 사례 모두에서 확인되는 것은, 프롬프트 기법만으로 결과물의 완성도가 보장되지 않으며 실행 환경과 조건을 명확히 요청하고 결과물을 직접 확인하는 사람의 역할이 필요하다는 점입니다.* 

### 한계와 주의점

바이브 코딩은 코딩 경험이 없는 사람도 아이디어를 곧바로 작동하는 결과물로 만들 수 있게 해 주었지만, 그만큼 주의해야 할 점도 분명합니다. 앞선 사례에서 확인된 한계와 주의할 점은 다음과 같습니다.

- **AI의 "완성했다"는 말은 검증된 사실이 아닙니다.** GPT는 버튼이 작동하지 않는 사이트를 두고도 자신 있게 완성되었다고 안내했습니다. AI의 설명은 직접 실행해 확인하기 전까지는 검증되지 않은 주장입니다.
- **결과물이 초보자에게 맞지 않을 수 있습니다.** Claude는 보안 장치까지 갖춘 설계를 내놓았지만, 설치와 서버 실행이 필요해 초보자가 바로 쓰기 어려운 결과물을 만들었습니다.
- **같은 요청도 결과가 매번 달라집니다.** AI, 프롬프트, 실행 시점에 따라 결과가 달라지며, CoT 같은 프롬프트 기법도 설계를 더 꼼꼼하게 만들 뿐 완성도를 보장하지는 않습니다.
- **겉으로 잘 돌아가도 보안 문제가 숨어 있을 수 있습니다.** 중복 투표 허점이나 입력값 검증 누락처럼 눈에 보이지 않는 문제는 실행 화면만으로 발견하기 어렵습니다.
- **안전하게 활용하려면 세 가지 습관이 필요합니다.** 실행 환경과 조건을 구체적으로 요청하고, 결과물을 직접 실행해 동작을 확인하며, 코드를 이해하고 점검할 수 있는 최소한의 코딩 지식을 갖추는 것입니다.

> *결국 AI는 구현을 대신해 줄 수 있어도 결과에 대한 책임까지 대신해 주지는 않으며, 그 책임은 끝까지 사용자에게 남습니다.*
